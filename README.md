# Seat Care

## Flutter 사용자 앱 · 실제 데이터 공유 (2026-10-23)

사용자용 Flutter 앱은 [`apps/worker-flutter/`](apps/worker-flutter/README.md)에 별도로 구성했습니다. ESP32 BLE 수신·보정·개인 기준·수행 기록과 공유 큐를 처리하고, 관리자 웹의 `/sensor/`가 공통 `/api/telemetry`에서 센서 상태·기록을 조회합니다. 서버 설정과 초대 발급은 [Flutter 공유 문서](docs/flutter-sharing.md)를 참고하세요.

현재 로컬 소스·테스트·HTTP 왕복 검증 단계입니다. 실제 서버 배포, APK/IPA 빌드, 실물 BLE 시험은 아직 완료하지 않았습니다. 아래의 웹·Capacitor 설명은 기존 구현에 관한 내용이며, Flutter의 구현 범위는 별도 README를 기준으로 합니다.

## 인터뷰용 원격 시연

별도 [시연 조종실](https://seat-care-admin.vercel.app/rehearsal/)에서 전용 키로 접속합니다. 조종실이 제공하는 근로자·관리자 초대 링크를 각 기기에서 열면 서로 다른 네트워크에서도 같은 시연 장면을 표시합니다. 기존 실제 센서 화면 대신 이 전용 시연 링크를 사용하세요.

5개 알림 장면은 기본 착석에서 점진적으로 진행한 뒤 알림을 표시합니다. 4·8·12초 속도, 지속 부위·예시 시간, 4초 압력 감소 장면, 근로자 반응 전달을 지원합니다. 사용법과 개발 설정은 [원격 시연 문서](docs/rehearsal.md)를 참고하세요.

ESP32-C3의 압력 센서 5개를 받는 근로자용 웹입니다. **현재 진행 범위는 웹사이트를 화면에 열어둔 동안의 측정·자세 판단·주의 알림**입니다. Vercel에 정적 웹으로 배포하며 앱 설치는 필수 과정이 아닙니다.

- 기본 알림: 모든 페이지 위쪽의 화면 알림. 시스템 알림 권한 없이 표시합니다.
- 선택 알림: 사용자가 켜는 알림음, 지원 브라우저에서 허용한 시스템 알림.
- 안정적인 개인 기준 등록 후 센서 부위별 부하 증가 지속 또는 압력 완화 미확인 시간에 따라 알림. 기본값은 편중 10초·완화 유지 20초·미확인 30분·재알림 1분이며 모두 검증 전 개발값입니다.
- 다른 탭/앱으로 이동하거나 화면을 잠그면 웹 판단·알림·기록 집계를 멈춥니다. 돌아오면 새 수신값부터 연속 시간을 다시 판단하며, 쉬는 동안의 시간을 소급 기록하지 않습니다.
- **Android Chrome 등 Web Bluetooth 지원 브라우저에서 실제 방석에 연결합니다. iPhone Safari는 Web Bluetooth를 지원하지 않아 현재 시연 화면·화면 알림만 확인할 수 있습니다.** iPhone의 실제 센서 수신은 Wi-Fi/서버 중계 등 별도 데이터 경로가 필요하며 아직 구현하지 않았습니다.
- 잠금 화면·닫힌 웹·강제 종료 후 알림은 현재 범위에 포함하지 않습니다.

## 보관 중인 설치 앱 코드 (현재 진행 범위 제외)

앞서 추가한 Capacitor Android/iOS 코드는 이전 구현 기록으로 보존했습니다. 설치 앱이 필요해지면 사용자 결정에 따라 Flutter로 진행합니다. 이번 멘토링 기능은 웹에 적용했으며 보관 앱 코드와 동기화하지 않았습니다. 현재 웹 기능 확인이나 Vercel 배포에는 아래 과정이 필요하지 않습니다.

```sh
npm run native:sync
npm run native:android
npm run native:ios
```

- Android: Android Studio, SDK 36, JDK 21 이상 환경에서 빌드합니다. BLE 연결 중 `connectedDevice` foreground service가 센서 수신·판정·기록·주의 알림을 처리합니다. 알림함에 감지 서비스와 중지 버튼이 표시됩니다.
- iOS: Capacitor 8에 맞는 Xcode 전체 설치가 필요합니다. Core Bluetooth `bluetooth-central` 백그라운드 모드와 상태 복원 식별자를 사용합니다. 수신 이벤트에서 Swift가 판정·기록·로컬 알림을 실행합니다.
- 웹 JavaScript의 타이머를 백그라운드 감지 수단으로 사용하지 않습니다.
- 강제 종료/강제 중지, Bluetooth·권한 해제, OS의 앱 실행 제한 뒤 감지는 보장하지 않습니다. 앱을 열어 상태를 확인하고 재연결해야 합니다.
- 실제 기기 설치에는 서명 및 배포 설정이 필요합니다. 현재 Mac에는 Xcode 전체·Java·Android SDK가 없어 APK/IPA 빌드, 물리 센서 연결, 잠금 화면 알림 전달은 미검증입니다.

## 기능

1. 기기 코드·QR/바코드 스캔, BLE 연결, 원본 5채널 프로토콜 수신
2. 빈 방석 5초 영점 → 평소의 편안한 착석 상태로 5초 기기 보정
3. 기기 보정과 별개로 10초 안정적인 개인 착석 기준 등록. 좌우 비대칭 허용, 실물 센서 위치·순서 확인 필수
4. 개인 기준보다 30% 이상 부하 증가가 이어지면 주의, 20% 이하로 회복하면 해제. 불안정·누락·포화 입력은 등록 거부/관측 중단
5. 부위 선택 → 확인 준비 → 실제 30% 부하 감소 → 유지시간 충족 → 수행 기록. 버튼 클릭·알림 확인은 수행이 아님
6. 부하 재증가·통신 공백·화면 숨김 시 확인 중단. 짧은 변화 0.5초는 유예하지만 유지시간에 포함하지 않음. 같은 감소 구간 중복 완료 방지
7. 좌면 전체 부하 해제는 원인 미확인으로 분리. 낙상이나 완화 성공으로 처리하지 않음. 다른 부위 증가도 별도 유지
8. 개인별 편중 지속·완화 목표·미확인 알림·재알림·안내 방식 설정, 알림 끄기/재개/5분 미루기
9. 날짜별 완료 횟수·유효 유지시간·중단·관측 공백·알림 타임라인. 계정 및 시연/센서별 IndexedDB 분리
10. L1/R1/L2/R2/C1 실시간 상대 부하 지도, 5초 간격 기록 재생, JSON 원본 내보내기
11. 권한 없는 화면 알림·테스트, 선택 알림음·시스템 알림, 큰 글씨, 시연 시나리오
12. 웹 Google/Apple 로그인 연결 코드 (별도 Firebase 설정 필요)

현재 웹의 핵심 지표는 개인 기준 대비 변화와 실제 관측한 완화 조건 충족입니다. 기존 방향별 점수는 이전 원본 로그에 남아 있지만 현재 핵심 지표로 사용하지 않습니다. 지도는 5점 보간이며 물리 압력 단위나 의학적 위험도가 아닙니다. 임계값·시간은 사용자/지원자 및 실측 검증이 필요한 개발값입니다.

수행·알림 이벤트는 최근 90일, 최대 20,000개를 보관하며 원본 프레임은 최근 7일입니다. 기준값·설정 버전·배치·세션·출처를 이벤트와 함께 보존합니다. 재연결/새로고침 후 과거 기준을 자동 적용하지 않고 다시 등록합니다. 서버·관리자·지원자에게 전송하지 않습니다.

### 시연 순서

기기 → 센서 없이 시연 시작 → 빈 방석 측정 → 앉은 자세 측정 → 개인 기준 등록(10초) → L1 선택·압력 완화 확인 시작 → L1 부하 감소 → 5초 유지 → 기록에서 조건 충족 확인. 시연은 편중 3초·완화 유지 5초·미확인 1분으로 단축되어 실제 센서 설정과 분리됩니다. 불안정한 입력·수신 끊김·미착석 버튼으로 등록 거부와 확인 중단을 시험할 수 있습니다.

## 계정

`.env.example`의 네 가지 **본인 Firebase 웹 설정**을 Vercel 환경변수에 입력한 뒤 재빌드하세요. 로컬은 `node --env-file=.env tools/build.mjs`로 환경변수를 읽을 수 있습니다. Firebase Console에서 Google/Apple 제공자, 웹 승인 도메인, Apple 서비스 정보를 별도로 설정해야 합니다. 팀원의 Firebase 계정이나 키를 재사용하지 않았습니다.

설정이 없으면 기기 내 로컬 모드로 동작합니다. 웹 기록은 계정별 IndexedDB 저장 공간에 분리하고, 설치 앱 기록은 해당 기기에 저장합니다. 로그인은 클라우드 기록 동기화를 뜻하지 않습니다. 원본 Flutter 앱과 마찬가지로 네이티브 화면에는 계정 로그인을 강제하지 않습니다.

## 관리자와 기존 시연

기존 웹·관리자 시연은 `npm run dev:demo`로 유지합니다 (근로자 4174 / 관리자 4173). 이 모드는 가상 서버 상태를 공유합니다. 새 실제 센서 기록은 관리자에게 자동 전송하지 않습니다. Vercel의 관리자 전용 사이트와 근로자 웹 `/admin/`에는 기존 관리자 대시보드를 제공합니다. 최초 화면은 원격 공유 미연결이고, 사용자가 시작하는 가상 시연은 해당 브라우저 메모리에서만 실행됩니다. 시연을 종료하거나 새로고침하면 초기화됩니다. 실제 휴대폰·관리자 사이 동기화나 외부 알림 전송은 없습니다. 계정별 권한·원격 저장소·동의 범위를 갖춘 관리자 연동은 별도 구현 대상입니다.

이전 문서는 `docs/legacy-readme-2026-10-07.md`에 보존했습니다. 현재 구현과 검증 경계는 [통합 보고서](docs/sensor-integration-2026-10-11.md)를 우선합니다.

## 검증

```sh
npm run check
npm test
npm run build
npm run test:swift
```

`npm test`는 기존 시연 검증과 새 프로토콜·자세·알림·기록·BLE 모의 통신 검증을 포함합니다. `test:swift`는 실제 Swift 소스의 순수 규칙을 추출해 실행하며 iOS 앱 빌드 성공을 뜻하지 않습니다. Android JUnit 검증은 `android/`에서 `./gradlew testDebugUnitTest`로 실행합니다.
