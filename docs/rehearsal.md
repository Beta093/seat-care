# 인터뷰 원격 시연

관리자 배포 사이트의 `/rehearsal/`은 센서 없이 진행하는 별도 상황극이다. 기존 근로자 측정 화면, 개인 기준, 수행 기록과 연결하지 않는다. 근로자용과 관리자용 전용 시연 화면은 기존 서비스의 HTML·CSS와 주요 화면 템플릿을 재사용하고, 같은 서버 장면을 표시한다. 휴대폰과 노트북은 같은 Wi-Fi일 필요가 없다.

## 사용

1. 진행자는 조종 키가 포함된 전용 링크로 `/rehearsal/`에 접속한다.
2. 조종실에서 근로자 링크와 관리자 링크를 복사해 각 기기에서 연다. 조종 링크는 관객에게 전달하지 않는다.
3. 오른쪽/왼쪽/뒤쪽/앞쪽/같은 부위 지속 중 장면을 선택한다. 첫 시작은 기본 착석 2초 후 부하가 서서히 증가한다. 이후에는 현재 표시 중인 압력 분포에서 다음 장면으로 바로 이어지며, 전환 중 다시 선택해도 그 순간의 분포부터 시작한다. 오른쪽에서 왼쪽으로 바꾸면 오른쪽 부하는 줄고 왼쪽 부하는 높아진다. 압력 전환만으로 알림을 띄우지 않는다. 조종실의 ‘알림 보내기’를 누르면 현재 선택한 편중 부위와 안내가 근로자·관리자 화면의 중앙 팝업에 나타난다. 총 진행시간은 4·8·12초 중 선택한다(기본 8초).
4. ‘같은 부위 지속’의 부위와 지속시간을 선택한다. 이 시간은 실제 기다린 시간이 아닌 가상 예시다.
5. 근로자의 ‘조정해볼게요’ 또는 ‘도움이 필요해요’ 반응은 조종실과 시연 관리자에게 전달된다. 버튼만으로 개선하지 않는다.
6. 진행자가 ‘압력 감소 장면’을 누르면 현재 분포에서 4초 동안 부하가 줄어든 뒤 개선 예시를 표시한다.
7. ‘기본 화면’으로 4초 동안 서서히 되돌리거나 ‘시연 종료’로 마친다.

초기 진입이 늦거나 새로고침해도 서버 시각을 기준으로 현재 장면의 진행 위치를 따라간다. 기본 조회 주기는 2초여서 각 기기의 네트워크에 따른 전달 지연은 있다. 조종실의 표시 확인은 해당 화면이 현재 장면을 받아 표시했다는 응답이며, 사람이 읽었다거나 도움을 받았다는 뜻은 아니다. 백그라운드 탭은 조회를 쉬고 복귀하면 다시 읽는다.

## 구조 및 운영

- `apps/rehearsal/`: 조종·근로자·관리자 시연 화면. 원래 센서 앱의 부하 보간 함수와 위치를 공유한다.
- `packages/shared/src/rehearsal.js`: PDF의 5개 알림, 기본/감소 장면, 시간 기반 전환 및 역할별 변경 규칙.
- `api/rehearsal.js`: Vercel 서버 함수. 비공개 Blob의 현재 상태를 조건부 쓰기(ETag)로 갱신한다. 인스턴스 메모리에 의존하지 않는다.
- 저장소 조회는 캐시와 응답 압축을 끈다. 압축 응답의 weak ETag는 조건부 쓰기에 사용할 수 없어, 1KB 이상으로 상태가 커진 뒤 장면 전환이 막히는 문제를 방지한다.
- 서버 환경변수: `BLOB_READ_WRITE_TOKEN`, `REHEARSAL_CONTROL_TOKEN`. 키를 프론트엔드 번들에 넣지 않는다. 읽기용 역할 키는 서버에서 도출하며 초대 URL의 fragment를 통해 각 화면에 전달한다.
- 단일 시연방. 동시에 여러 진행자가 조종하면 최신 장면 기준 확인 후 재시도한다. 시연 장면은 8시간 뒤 비활성화한다. 별도 참가자 정보·센서 원본·인터뷰 답변은 저장하지 않는다.
- Production은 `seat-care-rehearsal/current.json`, Preview는 `seat-care-rehearsal/preview.json`을 사용한다. 장기 이벤트 아카이브는 만들지 않는다.
- 조종 키 로컬 사본은 Git과 배포에서 제외되는 `.env.rehearsal.local`에 있다. 잃어버렸을 때 이 파일로 전용 링크를 다시 구성할 수 있다.
- 로컬: `npm run dev:rehearsal`. 별도 메모리 서버를 사용하며 온라인 저장소와 공유하지 않는다.

## 검증 범위

기존 106개 및 원격 시연 7개를 포함한 Node 테스트 113개, JavaScript 구문 검사, 정적 빌드. 역할별 권한, 장면별 지도, 동시 반응 충돌, 중복 요청, 오래된 반응 배제, 점진적인 압력 증가/감소를 검사한다. 실제 센서 또는 의학적 효과를 검증하는 기능은 아니다.

2026-10-12 공개 Production 주소에서 인증 없는 API 조회 401, 조종 명령 저장, 역할별 동일 revision 조회, 두 화면 수신 응답을 확인했다. 브라우저에서는 오른쪽 알림, 뒤쪽으로 점진적 전환(근로자 70%·관리자 71%인 인접 시점 관측), 마지막 알림, 근로자 도움 반응의 관리자 전달을 확인했다. 모바일 폭에서는 지도·알림·두 반응 버튼을 육안 확인했다. 서로 다른 실제 이동통신 기기를 사용한 현장 시험은 별도이며, 이 검증은 인터넷의 배포 서버에 접속한 브라우저와 API 클라이언트 기준이다.

같은 날 저장소 응답 압축에 따른 ETag 문제를 수정한 뒤 Production에서 관리자 확인 반응 저장, 압력 감소 전환과 양쪽 수신, 오른쪽 장면 재시작을 재검증했다. 양쪽 화면의 전환 중간 단계(25%·26%)와 마지막 알림을 확인했다.

## 기존 화면 재사용 (2026-10-12)

- 근로자: 기존 `apps/mobile-web/index.html`, `styles.css`, `worker.css`를 그대로 사용한다. 홈 템플릿은 `worker-status-view.js`로 분리하여 실제 근로자 앱과 시연 화면이 공유한다.
- 관리자: 기존 `apps/admin-web/index.html`, `styles.css`를 그대로 사용한다. 모니터링과 조치 기록 템플릿은 `packages/shared/src/admin-view.js`를 공유한다.
- `/rehearsal/?view=worker`와 `?view=admin` 주소와 초대 키는 유지한다. `viewer.js`가 서버 장면을 기존 화면의 압력 지도·상태·안내에 표시하며, 조종실은 별도 화면으로 유지한다.
- 근로자 요약·기록·기기 메뉴와 관리자 모니터링·조치 기록 이동, 큰 글씨 기능을 제공한다. 기록은 현재 시연 장면의 반응만 표시하고, 기기 화면은 시연 연결 상태를 안내한다. 실제 센서 연결·로그인·개인 기준·센서 저장소는 실행하지 않는다.
- 근로자 도움 반응과 관리자 안내 확인을 두 화면 및 조종실에 공유한다. 알림은 조종실에서 직접 발송하며 두 화면의 중앙 팝업에 나타난다.
- 분리 전과 후의 원본 근로자 홈 8개 조건, 관리자 2개 경로의 HTML 출력이 동일함을 비교했다. 기존 113개 테스트, 구문 검사, 빌드를 통과했으며 브라우저에서 점진 전환·도움 반응·관리자 확인·기록과 기기 경로를 확인했다.

Production `dpl_GafsJSDbubMbTjg9ruquWeiysBBS` 반영 후 공개 URL의 CSS 3종과 로컬 원본이 일치함을 확인했다. Safari의 기존 근로자·관리자·조종실 탭을 갱신하여 같은 오른쪽 편중 장면과 온라인 연결을 확인했다. In-app Browser의 배포 화면도 갱신했으며 콘솔 오류는 없었다.

장면 연속 전환: 현재 보간 압력을 다음 장면의 시작값으로 저장한다. 완료한 편중 장면과 전환 도중 모두 기본 압력으로 초기화하지 않는다. 오른쪽→왼쪽의 채널별 증가·감소, 중간 재전환, 같은 장면 재선택, 종료 후 새 시작을 추가 검증하여 총 116개 테스트가 통과했다.

## 수동 팝업 알림

- 조종실의 ‘화면 알림’에서 편중 부위와 안내 문구를 미리 확인한 뒤 ‘알림 보내기’를 누른다. 압력이 이동하는 중에도 보낼 수 있고, 압력 장면의 시작 시각이나 분포는 바꾸지 않는다.
- 오른쪽·왼쪽·앞쪽·뒤쪽 편중을 제목에 표시한다. 같은 부위 지속은 선택한 부위와 예시 지속시간을 함께 표시한다.
- 근로자 팝업에는 조정/도움 응답, 관리자 팝업에는 안내 확인을 제공한다. 응답 성공 시 해당 팝업이 닫힌다. ‘닫기’나 Escape는 팝업만 닫으며 확인·압력 개선 기록을 만들지 않는다.
- ‘알림 다시 보내기’는 새 팝업을 표시하고 이전 응답을 초기화한다. ‘알림 내리기’, 장면 변경, 시연 종료는 기존 팝업을 내린다. 과거 알림에 대한 늦은 응답·수신 확인은 새 알림에 적용하지 않는다.
- 브라우저 화면 안의 팝업이다. 문자·OS 푸시를 발송하지 않는다. 조회 간격은 2초이며 화면이 숨겨져 있으면 복귀 시 현재 알림을 확인한다.
- 총 119개 테스트 통과. 로컬 브라우저에서 수동 발송 전 대기, 양쪽 방향 표시 팝업, 응답과 관리자 확인, 재발송 시 재표시를 확인했다.
