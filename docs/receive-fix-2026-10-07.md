# Safari 수신 지연·빈 기록 후속 수정 (2026-10-07)

## 관측과 원인 구분

GUI 검증 작업 01a115e8-2f31-713f-9c29-3f9acd364084에서 근로자/관리자의 값과 최근 수신 시각이 서로 다른 시점에 머물고, 기록 시작 후 관리자 탭을 확인하면 두 번째 프레임이 없어 저장 불가한 현상이 보고됐다.

코드에서 확인한 원인 구조: client.js는 250ms 타이머만 사용하고 visibilitychange/focus/pageshow/hashchange 복귀 갱신이 없었다. 진행 중인 조회가 끝나기 전에는 다음 조회를 막았다. 기록은 브라우저 onSnapshot 콜백에 종속되어 응답이 없는 동안 프레임이 없었다. 동일한 숫자를 제외하는 정책은 없었다.

Safari에서 실제로 타이머가 제한됐는지, 요청이 정지됐는지, 다른 런타임 오류가 있었는지는 네트워크/콘솔 추적이 없어 확정하지 않는다. 아래 변경은 확인된 수신 복귀 취약점과 브라우저 수신 종속 기록 구조를 수정한 것이다. Safari 증상 해소 여부는 별도 GUI 재검증이 필요하다.

## 변경

- 탭 표시 복귀·창 포커스·페이지 복원·온라인 복구·앱 메뉴 변경에 즉시 조회한다. 숨김/복귀 시 오래된 조회를 취소하고 요청 식별과 세대로 지연 응답의 역전 적용을 차단한다. 복귀 직후에는 수신 대기로 표시하고 실제 새 응답 이후 연결 상태를 복원한다.
- 기록은 localhost 서버의 실제 가상 입력 tick에서 수집한다. 최소 250ms 간격(현재 tick에서는 약 300ms)으로 같은 수치의 새 입력도 기록한다. 브라우저 탭 이동과 조회 중단에 영향을 받지 않는다.
- 같은 오래된 스냅샷, 채널 누락·지연·중복·오류 입력은 새 프레임으로 기록하지 않는다. 누락 구간을 보간하거나 복원하지 않는다. 기록 수·실제 프레임 기간·오류 제외 수를 표시하고, 파일 재생 중 1.5초 넘는 프레임 공백에는 값/지도 대신 공백을 표시한다.
- start/stop은 세션 id로 멱등 처리한다. 응답 유실 시 같은 id로 재시도하고 지연된 status가 완료된 기록을 다시 활성화하지 못한다. 요청 중 버튼은 중복/교차 조작을 막는다. 관리자 포트에서는 기록 API를 거부한다.
- 파일 형식 v1과 브라우저 내부 파일 불러오기는 유지한다. 패턴 기준·추정은 녹화 파일에 포함하지 않는다. 서버 재시작 시 기록은 사라지며 세션은 최대 20분 보관한다. 새로고침 전 중지·저장이 필요하다.
- 추정 규칙·1.5초 stale 기준은 그대로다. 실제 센서 모델·물리 좌표는 여전히 미확정이며 가상 5점 배치다.

## 회귀검사

- npm test: 56개 통과. 복귀 이벤트 즉시 조회, 중단된 조회 취소/역전 응답 무시, 같은 값 반복 수신, 1분 동안 브라우저 수신 없는 서버 기록, 오류 구간 미보충, 오래된 스냅샷 중복 배제, start/stop 응답 유실 재시도, 세션 분리 포함.
- npm run check: 모든 JavaScript 구문 검사 통과.
- tools/pattern-smoke.mjs: 기존 기준 등록/추정·관리자 동기화/오류 보류/복구 검사 통과.
- tools/recording-smoke.mjs 실제 서버 검사: 60초 동안 사용자·관리자 상태 API를 조회하지 않았고 197개 프레임/59,846ms를 수집했다. 시작/중지 멱등, 동일 수치 기록, JSON 검증/재로딩, 관리자 기록 API 403 통과. 이는 브라우저 다운로드 UI 검사가 아니다.

## GUI 재검증 요청

두 화면을 새로고침해 변경 모듈을 읽은 뒤 다음을 확인한다.

1. 기준 등록 → 시연 도구 오른쪽 비중 → 즉시 요약. 전환 중 보류 후 안정되면 오른쪽 추정으로 갱신되는지, 관리자 탭 복귀도 최신 시각을 받는지 확인한다. 앞/뒤/중앙도 반복한다.
2. 새 기록 시작 → 관리자 탭에서 60초 확인 → 근로자 복귀 → 기록 중지. 수집 프레임 수와 기간, 저장/미리 재생 활성화, 파일 다운로드·열기를 확인한다.
3. 수신 지연·누락 구간에는 화면 판단 불가와 지도 숨김, 기록의 오류 제외 수 증가, 복구 후 실제 프레임만 이어지는지 확인한다.
4. 시작/중지 반복 클릭·시작 요청 중 다른 기록 버튼·취소·저장 재생/Esc 전환을 확인한다.

이 실행 환경에는 로컬 Safari/CUA 도구가 여전히 없으므로 직접 GUI 검증했다고 주장하지 않는다. 부모가 전달한 기존 GUI 통과(101개/10초 기준 등록, 중복/취소, 관리자 5방향, 오류 숨김, 재생 구분/Esc)와 이번 수정 후 회귀검증은 별개다. 정확한 360×640·큰 글자, 모호 경계, 모든 방향 양쪽 동기화, 실제 파일 저장/로드는 별도 GUI 확인이 필요하다.

## 보존

변경 전 Desktop 프로젝트는 작업공간 seat-care-before-receive-fix에 백업하고 전체 SHA256 manifest를 기록했다. 원본이 변경되지 않았을 때만 변경 파일을 적용한다. coin 프로세스/폴더·다른 앱/Notion·보안 권한은 변경하지 않았다.


## 원본 적용 후 최종 확인 및 서버 복구

원본에서 서버를 재시작한 뒤 같은 60초 무조회 검사를 통과했다. 199개 프레임/59,998ms 수집, 동일값 저장, 시작·중지 멱등, JSON 재로딩, 관리자 API 차단을 확인했다. 변경 13개 파일의 적용 당시 바이트 일치도 확인했다.

이후 exec-server 연결이 끊기면서 당시 최종 결과 추가 기록은 실행되지 않았으며, 후속 확인에서 4173/4174 모두 연결 거부를 반환했다. Mac 실행 환경 복구 후 원본의 기존 npm run dev 명령으로 SeatCare 두 서버만 재시작했다. 다른 프로세스·포트는 변경하지 않았다. 이 실행은 GUI 재검증용 로컬 개발 서버이며 호스트 실행 세션 중단 시 다시 종료될 수 있다.


## 후속 GUI 결과와 Esc 수정

부모의 GUI 재검증에서 양쪽 탭 복귀 동기화, 396프레임/119.6초 기록·미리 재생·종료 버튼은 통과했다. 새로 발견된 재생 중 Esc 문제와 서버 복구는 [Esc 후속 보고서](escape-fix-2026-10-07.md)를 참고한다.
